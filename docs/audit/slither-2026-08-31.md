## 深度人工审计第二轮（2026-08-31，逐行审读 6 合约全文 + 跨实现一致性核对）

**修复 1（高危，挑战押金制之前不存在、押金制引入后暴露）**：挑战成功路径的运营者退款
`require(okRefund)` 会把整个挑战交易原子回滚——而挑战的唯一对手方就是运营者本身。
恶意运营者把 operator 地址做成收 ETH 即 revert 的合约（或让自身进 token 黑名单，真实
USDC 黑名单是 revert 冒泡），即可让每一次合法欺诈证明原子回滚 → epoch 永不 voided →
债券机制对唯一需要防的人失效（审查欺诈证明向量）。**修复**：退款 push 失败不阻断挑战
（ETH `call` 返回 false / token `try...catch` 吸收 revert），资金留在合约记回
`settlementFunded`；新增 `withdrawRefund(epochId)` 拉取兜底（onlyOperator，仅 voided
epoch 开放——正常 epoch 结算资金归收款人 claim，绝不给运营者取回路径，防双花）。
slither 新报 `reentrancy-eth`（失败回记账在 call 之后）已定性：贷记方向 + 重入面闭合
（challenged/voided 先行、settlementFunded 清零，重入均被前置守卫拒绝），注释抑制。

**跨实现一致性核对（全对齐）**：
- `IntentHelper.computeIntentHash` ↔ `core/src/dsa.rs::intent_hash`：前缀 "INTv1\0" +
  agent(20) + delegationHash(32) + recipient(20) + amount_le(8) + category(32) +
  spendNonce_le(8) + memoTag(1)+memo(0|32) + expiresAt_le(8)，字段序与 LE 编码逐字节一致
  （golden vector 双侧锁定）。
- `Merkle` ↔ `aggregator/src/merkle.rs`：leaf = sha256(seq_le(8)‖hash(32))、EMPTY_LEAF =
  sha256("")、内部 sha256(left‖right)、treeDepth = log2(next_pow2(n))（n≤1→0）同构。
- `nettingRoot = keccak256(abi.encode(net))` ↔ `aggregator/src/lattice.rs::abi_encode_net`：
  head 偏移 0x20 + 长度 + 每行 address 左补 12B / amount BE u256，逐字节一致；Rust 侧
  `aggregate()` 用 BTreeMap 按 recipient 聚合 → net[] 恒一收款人一行且升序，杜绝
  kind2 挑战对重复收款人行的假阳性面。
- `DSA.sol` owner 区间 `[26:46]` ↔ `canonical_delegation`（"DSAv1\0" 6B 前缀 + agent 20B
  + owner 20B）一致。

**审读通过（无发现）**：DSA（低位 s 防延展性 + sha256≥群阶时 ecrecover 归零自然落入
BadOwnerSignature）、RevocationRegistry（owner 单一来源 DSA.ownerOf 不漂移）、claim/
commit/settle/`_verifyFraud`（DuplicateIntent + BadFraudKind 双守卫、押金入场前后
revert/原因码分流、CEI 顺序）。

**记录在案的已知边界（不修）**：net[] 长度无上界（结算资金随长度线性，DoS 面只在
operator 自身上，块 gas limit 自然封顶）；commit epochId 无连续性强制（跳号无碍）；claim
push 失败可重试（claimed 位随回滚复位，收款人自选地址的既有语义）。

**回归**：forge test 73/73（68→73：ETH 拒收运营者挑战不阻断 / withdrawRefund 拉取兜底 /
EpochNotVoided 负向 / NothingToRefund 负向 / USDC 黑名单 false 路径 + revert 冒泡 catch
路径）；slither 复扫 10 结果全部已知设计族，零真问题残留。

## invariant fuzz：状态机随机序列锤炼（2026-08-31，四步路径 ②，commit `01cd74a`）

深度审计是"人眼读状态机"，本步换"机器随机踩状态机"：forge invariant testing
（`test/BatchSettlerInvariant.t.sol`，foundry.toml `[invariant]` runs=64 × depth=256，
每次 `forge test` 约耗 11s）。

**Handler 动作面（fuzzer 随机编排）**：顺序 epoch `commit`（随机 1-4 条意图、3 收款人池、
金额 1-500）→ `settle` 三模式（诚实 / 漏单 kind1 面 / 低付 kind2 面，恒按 Σnet 精确注资——
超额注资是未记账捐赠，会破坏守恒前提）→ 窗口内挑战两路（`challengeFraud`：证明从已提交
意图 × 落盘净额现场构造，kind1 候选=收款人不在 net[]、kind2 候选=行额 < 已提交总额；
`challengeGarbage`：空证明 → 驳回 + 押金销毁路径）→ `warp` 过窗逐条 `claim` → voided 后
claim 行为断言。时间推进 handler 制造窗口边缘压力。

**三条全局不变量（每个调用序列后全查）**：

1. **资金守恒**：`合约 ETH 余额 == ΣbondedAmount + ΣsettlementFunded − Σ已付 claim`。
   ghost 记账与 storage 同步增减；挑战成功按 settle 时记录的**原额**扣减（成功后 storage
   已清零不可再读——首版在此翻过车，fuzz 没跑就发现了）；押金销毁进出相抵不进 ghost。
2. **状态机单调**（全 epoch 枚举）：`settled ⇒ committed`、`challenged ⇒ voided`、
   `voided ⇒ challenged`（驳回永不置位）。
3. **voided 后 claim 必拒**：try/catch 行为旗（绕开 `fail_on_revert=false`——expectRevert
   的失败也会被吞，行为旗不会）。

**结果**：64 runs × 16384 调用全绿；覆盖健康（challengeFraud 2379 调用仅 ~17-19 revert
=欺诈证明绝大多数成立并 void、challengeGarbage/claim/commit/settle 大量 exercising）。
**mutation check 实证 harness 会咬人**：临时禁用 `claim` 的 voided 守卫 →
`invariant_voided_claim_rejected` 立即红（counterexample 序列完整给出），原样还原后全绿。
forge 全量 76/76（73 既有 + 3 不变量）。

## 跨实现差分 fuzz：Rust 生产实现 ⇄ Solidity 镜像（2026-08-31，四步路径 ③，S-57）

深度审计第二轮的「跨实现一致性核对」是**人工逐行读码 + 单个 golden vector**
（S-11a：`Merkle.t.sol` / `IntentHelper.t.sol` 各一）。本步把「读出来一致」升级为
「机器批量差分」：

- **生成器**：`contracts/rust-smoke/src/bin/difffuzz.rs`（splitmix64 固定种子
  `MERIDIAN`，跨平台位稳定，零新依赖）调 **Rust 生产实现本体**（`core::dsa::intent_hash`
  / `delegation_abi` / `delegation_hash`、`aggregator::merkle::{leaf, merkle_root,
  inclusion_proof}`、`aggregator::lattice::{abi_encode_net, netting_root}`）产
  140 向量 → `contracts/test/fixtures/differential.json`（顶层并行数组，方便
  forge-std `parseJson*Array` 一次拉全列）。
- **消费方**：`contracts/test/Differential.t.sol` 逐条比对 Solidity 镜像，四条
  交叉实现契约：① `IntentHelper.computeIntentHash`（64 向量）；②
  `DSA.sha256(delegationABI)` + owner 切片 [26:46]（32 向量）；③ `Merkle.leaf` /
  补齐根 / `computeRoot` 重推 / `treeDepth`（8 叶 + 10 树 + 10 证明 + 11 深度，
  树计数刻意混入非 2 幂打补齐分支）；④ `nettingRoot = keccak256(abi.encode(net))`
  （16 向量，**编码字节级**比对——比根更强，根失配可定位到编码层）。
- **边界值注入**：每 6 向量塞一个边界（0 / 1 / 2^32 / 2^63 / u64::MAX）+ 净额面
  零地址 / 全 ff / 零额——纯随机漏掉的端序/补齐/溢出分支。
- **门禁**：`verify.sh` 新步 **8b**——重生成 fixture 到 `target/` 与入库版本
  `cmp`（漂移闸：改任一侧规范不回填 fixture 即红；写 `target/` 不碰工作树）+
  forge 差分测试（步 8 已跑）。
- **第三实现锚**：fixture 全量向量经 Python 独立重算交叉确认（intent_hash ×64、
  delegation sha256、merkle 叶/补齐根、net 编码 ×16 + 纯 Python keccak-256 根
  ×16）——不是只有 Rust↔Solidity 两方。
- **mutation check（差分闸会咬人）**：① `IntentHelper.u64LE` 改大端 →
  `test_intent_hash_differential` 当场红；② `Merkle.EMPTY_LEAF` 值改全零 →
  `test_merkle_padded_root_differential` 当场红（counterexample 给出具体树）。
  原样还原后全绿。
- **本轮实现坑（差分闸自己咬的）**：测试首版把 `agent`/`recipient` 当 `string`
  解析后 `bytes(...)` 转换——那是 **ASCII 字节不是 hex 解码**，64 向量首个即红；
  改走 `parseJsonAddressArray`（20B hex 恰是 address）后全绿。另：forge-std
  `parseJsonBytesArray` 要求 hex 前缀，空 memo 需写 `"0x"` 而非 `""`。

**回归**：forge 84/84（76 既有 + 8 差分）；rust-smoke workspace fmt/clippy 干净
（difffuzz 自身零告警）。**诚实边界**：单向差分（Rust → Solidity 镜像），反向由
S-11d rust-smoke 三场景 + forge 全量兜底；固定种子不追新输入——要更宽输入面改
`SEED` 重生成并提交（漂移闸强制同步）。

**四步路径坐标**：① slither 全量+人工定性 → ② invariant fuzz → ③ 跨实现差分 fuzz →
